# Compact maps for 2-6 players

The 2026-10-31 audit and extensions are documented in [PHASE2_MAPS.md](PHASE2_MAPS.md).
Current footprints remain 52/54/54 m; the earlier percentages below describe
per-dimension reductions, rather than the newer brief's area target.

2026-10-30. All coordinates remain metres. These layouts replace outer sections;
no buildings, players, weapons or street models were globally scaled.

| Map | Previous playable dimensions | Revised | Reduction per dimension | Upper alternative |
|---|---|---|---|---|
| European Town | 66 x 66 m | 52 x 52 m | 21.2% | Covered market gallery, 2.8 m floor |
| Industrial Complex | 68 x 68 m | 54 x 54 m | 20.6% | Metal warehouse catwalk, 2.8 m floor |
| Modern City | 68 x 68 m | 54 x 54 m | 20.6% | Covered second-floor passage, 2.8 m floor |

Town has offset perimeter loops, a well plaza, market/shop courts, a garden hall
and a baker court. Industrial connects three walk-in warehouse/workshop interiors
to the loading square, goods yard, container yard and utility yard. City keeps
road/sidewalk variations, diner, shop, garden court and lobby shortcuts around
the plaza. The three networks are individually authored and asymmetric.
Each upper alternative has stairs at both ends, an open passage beneath the
middle deck (2.58 m clear height), physical side rails/window walls and supports.
Stairs rise 0.175 m per tread; roofs leave 2.5 m headroom above gallery floors.

The existing style generators, architectural kit, roofs, PBR textures, sun/HDR
environments, shadows and graphics presets are retained. This repository has
low/medium/high graphics presets; this change does not invent another preset.
Masonry joints prevent newly adjacent walls and curbs sharing surface planes.
Gallery posts are separated from deck/wall end planes. Existing geometry
overlap limits were retained.

## Authoring and exports

`tools/compact_layouts.py` holds the three authored networks, used by the existing
`layout_design.py`, `layout_industrial.py` and `layout_city.py` generators.
Town now also uses LayoutKit's existing covered-lot anchoring so lot decomposition
cannot split a gate. City sidewalk generation keeps covered openings clear.

`blender/scripts/lib/upper_routes.py` produces **one set of solid parts** consumed
by both terrain rendering and `collision_gen.py`. The route deck is suspended,
rather than a ground-filled terrace. `compact_dressing.py` checks prop footprints,
support, facade/door/stair clearance and prop spacing before spawn sampling. Lamp
arms can overhang while their bases stay supported. Wires whose poles were removed
are discarded. Practice targets avoid the well and other placed obstacles.

Five optimized additions use existing PBR materials: flower box, produce-filled
market crate, stone bollard, pump skid and street utility box. Existing barrels,
benches, planters, cart, pallets, shelving, containers, machinery, bins, signs and
bicycle racks remain available. The compact layouts place 51 / 23 / 35 props,
respectively, plus Town's central well. Automatic thin industrial lots now become
solid masonry; two explicitly authored thin fence segments divide the utility
equipment and storage parts of an accessible yard, with multiple openings.

Updated outputs include each map's building block GLBs, terrain, collision JSON,
collision debug GLB and map asset index; shared `props.json` and five new prop GLBs;
editable `blender/source/{european-town,industrial-complex,modern-city,props}.blend`;
and the asset manifests. The exporter removes only its obsolete numbered building
block outputs when a map needs fewer blocks. Textures/audio/weapons/characters are
not regenerated by this map update.

The three `docs/*-compact-plan.png` images show building footprints, ground and
covered routes, upper connections, yard dividers, props and spawn markers. They
are authoring diagnostics. No tactical map is added to the gameplay UI.

## Multiplayer and spawning

Sixteen spawn candidates per map are selected on the actual asymmetric network,
clear of props, targets, doors and upper stair/deck footprints. They cover all
quadrants and keep at least 4 m separation. The authoritative Worker spawn chooser
retains body/occupancy checks and prefers 8 m separation, fewer opponent sightlines
and then greater distance. It probes both torso and head visibility from actual
opponent eyes, conservatively ignoring facing direction. If every candidate is
exposed, it falls back to the least exposed clear candidate. Teammates still count
for occupancy/separation. No spawn immunity or client-assigned position is added.

Layout navigation metadata contains ground/covered rectangles, upper waypoints
and physical ground obstructions from the shared route parts. Legacy ground-query
helpers account for stairs/posts without treating suspended decks as solid walls.
The frontend and Worker import the same regenerated layouts, prop catalog and
collision files. Map revisions are recalculated from those inputs by the existing
`mapVersion` function. Protocol remains v6; the canonical room, match mode logic,
600000 ms rounds, session persistence and health/combat behavior are unchanged.

**Both frontend and Worker require publication together when authorized**, because
layout/collision hashes changed. An old Worker correctly rejects new frontend map
revisions. No commit, push or deployment is performed by this task.

## Reproduction and verification

PowerShell, from `C:\Users\Public\Crossfire`:

```powershell
python -I tools/layout_design.py --write
python -I tools/layout_industrial.py --write
python -I tools/layout_city.py --write
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b --factory-startup --python-exit-code 1 -P blender/scripts/generate_all.py -- --only props,town,industrial,city
python -I tools/compact_diagnostics.py
npm.cmd test
npm.cmd run typecheck
npm.cmd run assets:verify
$env:VITE_MULTIPLAYER_URL='ws://127.0.0.1:8787/ws'
npm.cmd run build
Remove-Item Env:VITE_MULTIPLAYER_URL
npm.cmd --prefix server run typecheck
npm.cmd --prefix server test
```

The direct Blender invocation preserves existing texture/audio outputs. Blender's
Windows thumbnail-cache warning does not affect the exported GLBs or saved sources.
Backend `test` includes a Wrangler **dry-run** build and real local Workers tests.
The local test build needs a configured WebSocket URL; the isolated browser test
redirects that endpoint to its actual Worker. This does not change production
configuration: GitHub Pages still uses the existing workflow's public Worker URL.

Map tests cover bounds, quadrant coverage, shared revision equality, major routes
belonging to cycles, ground connectivity with placed props, clear covered routes,
bidirectional controller traversal of all stairs/decks, underpass headroom and
ground support, yard fences and spawn choice against 1-5 opponents around each map.
The older geometry/asset/tactical/movement/combat/network tests remain enabled.
Ground connectivity probes terrain first, then the complete prop collision world;
crate tops are not miscounted as additional ground routes. The marker-direction
test chooses a real spawn with enough room for its complete stride.

After the production build, serve its GitHub Pages subpath in one terminal:

```powershell
node tools/serve-dist.mjs --port 4198 --base /crossfire/
```

Run focused browser checks in a second terminal:

```powershell
node tools/compact-maps-test.mjs --url http://127.0.0.1:4198/crossfire/
node tools/reconnection-test.mjs --url http://127.0.0.1:4198/crossfire/ --out test-results/compact-multiplayer
```

The first checks actual map loads, both stair directions, unchanged settings and
high-quality rendering captures. The second uses two real browser clients with an
isolated local Worker, actual sockets/shots and a 61-second stable connection test.
These are local validations; they do not establish public Cloudflare deployment
health or replace further human 2-6 player balance playtesting.
