# Asset pipeline

All game assets are generated by scripts. Nothing is hand-modelled, so every model can be rebuilt
and restyled from code. The generated files are committed so the game and CI do not need Blender.

```
tools/fetch_textures.py ──> public/assets/textures/shared/*.jpg, env/sky_*  (Poly Haven, CC0)
tools/make_procedural_textures.py ──> textures/european-town/*, shared/fx/*
tools/make_audio.py ──> public/assets/audio/*.wav
tools/layout_design.py ──> src/maps/european-town/layout.json, docs/european-town-plan*.png
blender/scripts/generate_all.py ──> GLBs, collision.json, materials.json, .blend sources, manifest
```

## Running Blender

```bash
npm run assets                                 # textures + audio + all Blender stages (~90 s)
npm run assets -- --only town                  # stages: materials, props, weapon, library, kit, town
npm run assets -- --only town --previews       # also EEVEE previews in docs/previews/
npm run assets:verify                          # sanity-check every output
```

Manual (Windows):

```bat
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --factory-startup -P blender\scripts\generate_all.py -- --only town
```

Developed and tested with Blender 5.2.3 LTS. The scripts use only stable `bpy`/`bmesh` APIs and the
built-in glTF exporter; Blender 4.2+ should work.

## Script layout

| File | Purpose |
|---|---|
| `generate_all.py` | Orchestrates stages, groups buildings into blocks, exports, writes the manifest |
| `lib/catalog.py` | *Pure data*: building types, palettes, prop sizes and colliders |
| `lib/materials.py` | *Pure data*: material table + `materials.json` writer |
| `lib/building_spec.py` | *Pure*: derived building dimensions (eave height, passages, rooms, chamfer, balcony) |
| `lib/collision_gen.py` | *Pure*: collision boxes for buildings, walls, terraces, stairs, arches |
| `lib/layout_util.py` | *Pure*: point classification and ground height over a layout |
| `lib/meshkit.py` | Mesh building in game coordinates, world UVs, vertex colours → Blender objects |
| `lib/bmat.py` | Blender preview materials from the material table |
| `lib/building.py` | Procedural townhouse generator (facades, openings, trims, roofs, passages, rooms) |
| `lib/roof.py` | Gable/hip roofs over any convex footprint (lower envelope of roof planes) |
| `lib/kit.py` | Facade kit: windows, shutters, doors, shopfronts, balconies, signs, lanterns |
| `lib/terrain.py` | Ground grid, terraces, stairs, garden walls with gates, flying arches, inlays |
| `lib/props.py` | Street props |
| `lib/weapon.py` | The VK-7 pulse carbine |
| `lib/modular.py` | Generic kit pieces for future maps |
| `lib/exporter.py` | Scene setup, linked-duplicate kit placement, GLB export, .blend saving |
| `preview_buildings.py`, `preview_file.py` | Development render helpers |

*Pure* modules have no `bpy` import and are shared with `tools/layout_design.py`, so dimensions and colliders cannot drift.

## How a building is made

1. `layout.json` gives the footprint rectangle, type, floors, palette, seed, roof type/ridge, doors and optional
   passages, rooms, chamfer, balcony or shopfront.
2. Each footprint edge is sampled to find which parts face open ground, a neighbour (party wall: only the part above
   the neighbour's eaves is built, without openings) or the outside.
3. Open facades get bays of windows per floor (ground floor: doors, shopfront, barred windows), real openings with
   reveals, plinth, string courses, cornice, quoins, downspouts, rain-streak vertex shading and rafter tails.
4. Passages get side walls and a vault (arch style, with voussoirs and spandrels) or a beamed ceiling (lintel style);
   rooms get interior walls, beamed ceiling, floor and a lantern.
5. The roof is the lower envelope of eave planes over the (chamfered) footprint, with overhangs except on party walls,
   gable walls, fascia, soffit, ridge caps, gutters and chimneys.
6. Windows, shutters, doors, sills, surrounds, balconies, signs are kit pieces placed as linked duplicates
   (`KIT_<piece>__<material>`), split per material.

Collision for the same building comes from `collision_gen.building_boxes`, using the same `building_spec` numbers.

## Z-fighting: rules the generators follow

Two visible surfaces on (nearly) one plane flicker. These are the rules that keep the town free of them; `tests/geometry.test.ts`
checks the exported models and `tools/dev-zfight.mjs` audits the whole baked scene (including props).

- **Overlay pieces own their footprint.** A window sill's top is the first 0.14 m of the opening's floor, so the facade
  generator starts its reveal floor behind it (`kit.SILL_BACK`). A door's plinth stops where its stone surround begins
  (`kit.SURROUND_B`). Stair treads are cut out of the ground cells exactly (`TerrainBuilder._cell_minus_stairs`), not by cell centre.
- **Wall ends beside a gateway are left out**; the gate's own jamb face covers that plane.
- **Neighbours' walls are not rebuilt.** A facade that faces another building's passage or room is a party wall
  (`edge_exposure` treats covered cells inside another building as `party`), because that building already has its side wall there.
- **Roof fascia is not built over a wall plane.** Edges without overhang are flush with the wall, which already reaches the roof.
- **Concave corners:** where two buildings' trims would fill the same corner square, the building with the lower id stops
  short; ends on a neighbour's plane drop their end face (`BuildingGenerator.run_end_cuts`).
- **Open shutters need room.** Leaves fold flat to either side of a window; if the gap to the next opening is too small
  they are drawn closed (`BuildingGenerator.shutter_room`).
- **Printed layers sit at least 8 mm proud** (shop sign face, door glazing, handle plates, nosing lips); props recess lids
  and keep foliage cards fanned apart so no two cards share a plane.
- **Ground inlays** use `decal` materials (`slabs_inlay`, `stone_inlay`, team strips) which get a polygon offset at runtime.
  This is the only use of depth bias; do not use it to hide overlapping geometry.

## Materials and textures

- `materials.py` is the single list of material names. Each entry references a texture set
  (`<key>_albedo.jpg`, `_normal.jpg` (OpenGL), `_orm.jpg` (AO/roughness/metallic)), a tile size in metres, a linear tint
  and PBR factors. It writes `public/assets/materials.json`.
- Blender materials (for the .blend files) are built from the same table with glTF-compatible nodes only.
- GLBs are exported **without images** (`export_image_format='NONE'`); the runtime binds textures by material name.
- UVs are world-space box projections in metres: textures keep a constant density across every model.
- Vertex colours (`COLOR_0`) carry grime: darker near the ground, under eaves, below windows, and contact darkening on
  the ground grid near walls. The runtime multiplies albedo by them and also bakes tints into them when batching.

### External assets

All external images come from Poly Haven under CC0; the list is in `public/assets/textures/CREDITS.md`
(`tools/fetch_textures.py` regenerates it). Procedural textures and audio are original.

Object origins: buildings at their footprint centre on the ground; props at the footprint centre on the ground facing
north (−Z); kit pieces at the opening's bottom centre on the wall plane; weapon at the top of the grip.
