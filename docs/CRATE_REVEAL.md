# Reward crate, crate skins and the Rich kill effect (2026-11-05)

The Shop now sells one server-authoritative **Reward Crate** for 300 gems. Opening it
plays a full-screen reveal of the item the Worker already granted. Six skin
collections, each with a version for all four weapons (24 items), make up the pool.
Weapon statistics, hitboxes, timing and clearance are unchanged. Gameplay protocol
stays **v19**; inventory HTTP schema stays **v1** and gains one endpoint. Nothing was
committed, pushed or deployed.

## Server crate (`POST /cosmetics/open`)

- Body is exactly `{version:1}` with the existing `Authorization: Bearer <career
  capability>`. It is routed to the canonical public-main object only.
- Inside the existing `exclusive()` gate the Worker checks gems >= 300 and picks an
  item with `drawCrate` (shared/cosmetics.ts), using `crypto.getRandomValues`.
- The gem spend (`career:<id>`, revision +1) and the grant (`inventory:<id>`,
  revision +1) commit in **one** `storage.put` batch, together with any other dirty
  career records. The cached profile is changed before the write, so an overlapping
  `persist()` cannot capture the pre-purchase balance; it is rolled back if the write
  fails. Expected failures (401/400/409) are responses, never gate rejections.
- Response: `{version:1, item, gems, inventory}` (validated by `validCrateResult`).
  The owner's connected public-main socket also receives the new career view.
- Odds: Uncommon 55%, Rare 40%, Legendary 5% (no Epic family exists yet; its old
  10% share was redistributed). Weights renormalize over rarities that still have
  unowned items, so a crate never repeats an item. With everything owned the
  endpoint returns 409 and the Shop shows ALL SKINS OWNED.
- Spending never changes lifetime statistics (earned gems stay cumulative).

## Collections

| Collection | Rarity | Finish |
|---|---|---|
| Green Camo | Uncommon | Woodland blobs: olive, brown, forest green, black |
| Blue Camo | Uncommon | Digital/urban pixels: navy, steel blue, light blue, slate |
| Red Camo | Uncommon | Tiger strokes: crimson, dark red, coral, black |
| Marble | Rare | White marble body, black marble grips, polished trim, clear coat |
| Rainbow Glow | Rare | Rainbow body with glowing circuit traces that scroll slowly; dark gloss grips |
| Rich | Legendary | Engraved gold with coin medallions, black lacquer and gold pinstripe grips, polished gold steel, clear coat; **money kill effect** |

Items are material overrides on the original default GLBs (`binding:'shared'`), so
anchors, moving parts, rigs, first person, characters and previews all work without
new geometry. A finish names library materials (`gun_black`, `gun_fde`, `gun_wood`,
`gun_polymer`, `gun_steel`) and applies only those each weapon actually has
(`WEAPON_MATERIALS`). IDs are `<collection>-<weapon>`, for example `rich-sniper`.

`CosmeticMaterial` gained `tile` (metres per repeat; weapon UVs are in metres),
`emissive`/`emissiveColor`/`scroll` and `clearcoat`. Textures are shared per
collection under `public/assets/cosmetics/skins/<collection>/` (1.7 MB total) and are
generated by `blender/cosmetics/skin_textures.py` (tileable FFT noise, run in
Blender's Python because system Python has no numpy).

Loader fix found while testing: outside Ultra, MaterialLibrary reads roughness from
the ORM **alpha** channel, and that flag overrides green. Skin ORMs are opaque RGB, so
every finish rendered fully rough (gold looked like cardboard). `CosmeticAssets`
now clears `useRoughnessFromMetallicTextureAlpha` when a finish supplies an ORM.

Isolated preview scenes (Locker preview, thumbnails, crate reveal) now use
`studioEnvironment()` (`assets/cosmetics/studio.jpg`, a generated softbox panorama)
for reflections; without it metallic finishes render nearly black. Map scenes keep
their HDR skies.

## Reward crate model

`blender/cosmetics/generate_reward_crate.py` builds an original rounded crate:
dark navy body, blue panels, ice-blue inlays, orange latches/grips/corner caps and
a white domed lid. Outputs: `public/assets/cosmetics/crate/reward-crate/model.glb`
(embedded PBR), a cropped transparent `thumbnail.png` (Shop) and the editable
`blender/source/cosmetics/reward-crate.blend`. Animated parts and pivots:

| Node | Pivot | Use |
|---|---|---|
| `crate_body` | floor centre | squash/stretch about the base |
| `lid_nw`, `lid_ne`, `lid_sw`, `lid_se` | each quarter's centre | one domed lid cut into quarters (bisected, so the closed lid reads as one shape) |
| `seam_glow` | lid base | emissive strips in the seams; tinted to the rarity at runtime |
| `core_glow` | body top | emissive panel revealed after the burst |

The loot-box screenshot and opening GIF mentioned in the brief were not in
`references_images/`; the design follows the brief's written description.

## Reveal sequence (`src/ui/CrateReveal.ts`, timing in `src/ui/crateTimeline.ts`)

1. Overlay opens; the closed crate drops in with a landing squash and idles while
   the server answers and the reward model loads.
2. 0-0.46 s: crouch and building shake (anticipation).
3. 0.46 s: stretch up, lid pops 12 cm with overshoot and hovers; seams light in the
   rarity colour, light shafts leak upward, sparks start; the background begins to
   pick up the rarity colour.
4. To 1.38 s: charge (seam glow and tremble grow).
5. 1.38 s: burst. The four lid quarters fly outward and up, tumble and fall out of
   frame. Body squash with a springy recovery, flash, 380-spark burst, rising light
   column, rarity background wipes out from the crate.
6. The reward shoots up with overshoot, spins once into the hero angle (side view,
   muzzle right and slightly toward the viewer); the camera tilts from looking down
   at the crate to looking slightly up at the reward. Rotating rays, floating motes
   and a rarity rim light frame it. Legendary rewards also get the money shower.
7. The name, rarity pill and weapon category animate in at the top; then EQUIP,
   OPEN ANOTHER and CONTINUE. Drag rotates the weapon (yaw and limited pitch);
   release keeps some flick, then a damped spring returns it the short way with a
   slight overshoot. SKIP or Escape jumps to the reveal. Server errors show in the
   overlay with BACK, and the crate stays closed.

Reveal colours: Uncommon `#39e57a`, Rare `#4d8dff`, Legendary `#ffc22e` (the
shared rarity names/colours are unchanged). Reduced motion keeps the beats but
removes shake and jitter and shortens the anticipation. One engine and scene, all
disposed on close or navigation. Test hook: `__crossfire.crateReveal(paused, seek)`.

## Rich kill effect (`src/weapons/MoneyBurst.ts`)

When an elimination's killer has a Rich-collection cosmetic (read from the
existing snapshot `cosmeticId`, `killEffect()`), gold coins and banknotes tumble
for about 1.3 s:

- **Killer:** camera-space emitter in the weapon render group, over the receiver and
  away from the crosshair.
- **Other players within 45 m:** world-space emitter at the killer's muzzle.

The effect uses two thin-instanced meshes (21 pieces per burst, at most 3 bursts),
CPU-integrated, with no physics and no new network messages. Both emitters are created
and shader-compiled when the match weapon loads, so the first kill does not hitch.
Hooks: `__crossfire.moneyBurst()` and `__crossfire.moneyInfo()`.

## Limits

- No new weapon geometry; finishes are textures on the existing models. Coin
  engravings become subtle at thumbnail size.
- Gem income is unchanged (challenges only), so opening all 24 items costs 7,200 gems.
- The Rich effect is not shown to a victim who is already spectating the killer's
  scoped first-person view.
- Headless Chrome frame times are not a target-device benchmark.
- Release requires the matching Worker (new endpoint) and frontend through the
  existing CI. An old Worker returns 404, which the Shop reports as an error.
